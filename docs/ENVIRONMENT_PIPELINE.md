# Environment pipeline (Blender → Godot)

## How assets are made

Every asset is generated by Python scripts in `tools/blender/` using Blender's own API. Nothing is modelled by hand, so any asset can be rebuilt, resized or restyled by changing code and re-running.

| Script | Builds | Outputs |
|---|---|---|
| `build_stage1_modular.py` | Walls, openings, windows, floors, ceilings, corridor slices and junctions, doors | `assets/blender/modular/FW_Modular_Kit.blend`, `assets/exports/modular/*.glb` |
| `build_stage1_props.py` | Clinical furniture, equipment, fixtures, security hardware, signage | `assets/blender/clinical/FW_Props_Clinical.blend`, `assets/exports/clinical/props/*.glb` |
| `build_stage2_chapter1.py` | 20 m clinical corridor, Interview Room A, psychiatrist's office | `assets/blender/clinical/FW_Chapter1_ClinicalWing.blend`, `assets/exports/clinical/env/*.glb` |
| `build_stage3_props.py` | Medication, ward-bed, linen and emergency equipment | `assets/blender/clinical/FW_Props_Clinical_Stage3.blend`, `assets/exports/clinical/props/*.glb` |
| `build_stage4_security_admin.py` | Security and admin props and the 11-room security and admin wing | `assets/blender/security/FW_Props_Security.blend`, `assets/blender/security/FW_SecurityAdminWing.blend`, `assets/exports/security/{props,env}/*.glb` |
| `build_stage4_research.py` | Research props and the 12-room research level | `assets/blender/research/FW_Props_Research.blend`, `assets/blender/research/FW_ResearchWing.blend`, `assets/exports/research/{props,env}/*.glb` |
| `build_stage5_historic.py` | Historic props and the 13-space asylum sublevel | `assets/blender/historic/FW_Props_Historic.blend`, `assets/blender/historic/FW_HistoricSubstructure.blend`, `assets/exports/historic/{props,env}/*.glb` |

Each script also saves preview renders to `assets/renders/` and merges its assets into `assets/asset_manifest/asset_manifest.json` (and `.md`).

### Running the scripts

Use Blender 5.0 or newer (free, <https://www.blender.org/download/>):

```bash
# macOS, from the repository root
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage1_modular.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage1_props.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage2_chapter1.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage3_props.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage4_security_admin.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage4_research.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_stage5_historic.py
```

The same scripts also run with the `bpy` Python module (`pip install bpy` on Python 3.11). That is how they were built in CI-style cloud sessions, where no Blender GUI or MCP connection was available.

The `.blend` files are editable sources: open them in Blender to inspect or tweak. If you edit a `.blend` by hand, re-export from it, or the next script run will overwrite your edits. Prefer changing the scripts.

## Conventions

| Topic | Rule |
|---|---|
| Units | Metres. Blender Z-up becomes Godot Y-up automatically on glTF import (Blender +Y → Godot −Z). |
| Grid | 0.5 m snap, 2.0 m primary module, 3.0 m floor-to-ceiling, 0.2 m walls centred on grid lines. Corridors are 3.0 m between wall centres (2.8 m clear). |
| Origins | Walls: left end at floor level, front face −Y. Floors and ceilings: −X/−Y corner. Corridor slices: centreline at slice start. Doors: opening centre at floor level, wall plane y = 0. Furniture: floor centre. Wall- and ceiling-mounted props: the mounting surface. |
| Names | `MOD_*` architecture, `DOOR_*` doors, `PROP_*` props, `ENV_*` assembled environments. |
| Collision | Nodes ending in `-colonly` become collision-only `StaticBody3D` in Godot (box proxies, separate from visual meshes). Decorative props have none. Door leaves carry their own proxy, parented to the leaf. |
| Doors | The leaf node's origin is the hinge: rotate it about Godot Y to open. The frame relies on the wall colliders. |
| Cameras | `CAM_*` are real glTF cameras (imported as Camera3D, not current). They are framing references only; cuts are decided in Godot. |
| Markers | `MARK_*` empties for seats, eye lines, standing and interaction points. Forward = Blender +Y = Godot −Z. |
| Lights | Never baked. `LIGHTMARK_*` empties mark where Godot should place lights, with hints stored as glTF extras (kind, colour, range). Blender preview lights live in a `PREVIEW_ONLY` collection and are not exported. |
| States | Alternate states are separate sibling nodes with `state_group`, `state` and `default_visible` extras (e.g. `OBS_Shutter_Open` / `OBS_Shutter_Closed`). Godot toggles visibility, so the canonical geometry is never modified, which keeps states save-safe. |
| Screens and signs | `PROP_Terminal_EHR_Screen` and `PROP_Sign_Room_Face` are separate meshes with 0–1 UVs, ready for a ViewportTexture or Label3D. |
| Materials | Shared PBR library (`fw_lib.PALETTE`): base colour, roughness, metallic, emission and alpha only. All export cleanly to glTF. No textures yet. |

## Chapter 1 shared frame

Place `ENV_ClinicalCorridor_20m`, `ENV_InterviewRoom_A` and `ENV_PsychiatristOffice` all at the Godot origin and they assemble into one cluster:

- **Corridor:** x 0, y 0 → 20 (Godot z 0 → −20). Walls at x = ±1.5; ward-entry double door at the north end.
- **Office:** west side, door at y = 5. Exterior window on its west wall.
- **Interview Room A:** east side. Secure door at y = 13, one-way observation window at y = 11.

Shared walls belong to the corridor asset, painted on their room side, so no wall is doubled.

## Validation

1. Each build script asserts that every asset has a visual mesh, has plausible dimensions and no unapplied scale. Environments must also have collision and camera markers, and the interview clinician must be seated nearer the exit than the patient.
2. `tools/godot/validate_glb_imports.gd` loads every `.glb` in Godot and checks meshes, generated collision, camera markers and manifest dimensions (±5 cm):
   ```bash
   godot --headless --path . -s res://tools/godot/validate_glb_imports.gd
   ```

`assets/blender`, `assets/renders`, `assets/asset_manifest` and `tools/blender` contain a `.gdignore`, so Godot never tries to import `.blend` files. Godot's `.blend` importer needs a local Blender path.
