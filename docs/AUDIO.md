# Audio system

The Forensic Ward's audio has three separate production pipelines feeding one Godot runtime:

| Pipeline | Tool | Output | Where it runs |
|---|---|---|---|
| Dialogue and announcements | Kokoro TTS (offline) | `audio/voice/<chapter>/<line_id>.ogg` | Any machine with Python 3.11+ |
| Sound effects, ambience, transitions | Procedural synthesis (`tools/audio/synth_sfx.py`) | `audio/sfx/`, `audio/ambience/`, `audio/music/` | Any machine with Python 3.11+ and ffmpeg |
| AI-generated score | ACE-Step 1.5 on Apple Silicon | `audio/music_ai/<track>/` | The Mac only: see [MUSIC_AI_MAC_GUIDE.md](MUSIC_AI_MAC_GUIDE.md) |
| Original soundtrack | Supplied by the owner | `assets/audio/music/` (used unmodified) | n/a: see [Soundtrack](#soundtrack) |

All three feed `AudioDirector` (`systems/audio/AudioDirector.gd`, autoload). The asset list is in [AUDIO_MANIFEST.md](AUDIO_MANIFEST.md). AI music has its own manifest, `audio/music_ai/manifest.json`, which is created when the first track is approved.

## Folder layout

```

tools/music_ai/          ACE-Step installer, server launcher, score plan, generator/importer

```

## Runtime (AudioDirector)

Buses (created at startup if no bus layout defines them):

| Bus | Player setting | Effects | Use |
|---|---|---|---|
| Master | `volume_master` | | |
| Music | `volume_music` | low-pass (intensity), amplify (dialogue duck) | music beds, stingers |
| Ambient | `volume_ambient` | | parent of AmbienceBed |
| AmbienceBed | (internal) | low-pass (night/room), amplify (dialogue duck) | location ambience |
| SFX | `volume_sfx` | reverb (per location) | one-shots, 3D sounds |
| Voice | `volume_voice` | light reverb (half the location's wet level) | dialogue |

API (all data-driven from `audio/cues.json`):

- `set_location(id)`: crossfades to the location's ambience for the current shift (`day`/`night`) and applies its room reverb. A shift can also name a `detail` layer, such as distant staff chatter or old intercom static, which crossfades over the base bed. Locations are `corridor`, `nursing_station`, `historical_wing` and `ward_zero`. `EventBus.shift_started` retargets the ambience automatically, using a 4 s crossfade.
- `play_sfx(cue)` / `play_sfx_3d(cue, position)`: plays a one-shot that frees itself when finished. 3D sounds use distance attenuation and filtering. Cues with a `streams` list, such as footsteps and key presses, play through an `AudioStreamRandomizer`, which picks a random take (never the same one twice in a row) with slight pitch and volume variation. For footsteps, call `play_sfx_3d("sfx_footstep_<vinyl|tile|concrete>", foot_position)`.
- `play_music(cue)`, `set_music_state(state)`, `set_music_intensity(0..1)`: a music state has calm/tense variants (`min_intensity`). Changing the intensity crossfades between variants over 4 s and opens the Music low-pass filter.
- `play_stinger(cue)`: one-shot transition. `duck_ambience_db` creates a controlled silence under it.
- `play_line(line_id[, emitter])` / `play_scene(scene_id)`: plays dialogue from `data/narrative`. `EventBus.subtitle_shown` fires when the voice starts, with the clip's exact duration, and `subtitle_cleared` fires when it ends or is skipped. `dialogue_line_finished(line_id, completed)` distinguishes natural completion from interruption for presentation-only listeners. Music ducks by 9 dB and ambience by 4 dB while anyone speaks, and both are restored 1.2 s after the last line. Unvoiced lines still show their subtitles.
- Naomi's Chapter 1 cue controller listens to those existing line IDs and lifecycle events. It never gates dialogue or story state. Optional `AnimationPlayer` clips use the cue's semantic body name; gestures can use a separate `GestureAnimationPlayer`. Rig-specific adapters may join `character_acting_adapter`, `character_face_adapter`, `character_gaze_adapter` or `character_gesture_adapter` and implement the corresponding methods in `scripts/acting/CharacterActingAdapter.gd`. Missing nodes and clips are no-ops with safe transitions. Speaking state follows the actual voice/subtitle window; no phoneme timing is fabricated.
- `start_music_context(id)` / `end_music_context(id)`: see [Soundtrack](#soundtrack).
- `trigger_event(id)`: also connected to `EventBus.narrative_event_fired`. It runs timed actions (`sfx`, `stinger`, `music`, `music_state`, `music_context`, `end_music_context`, `line`, `scene`, `intensity`). Events without audio are ignored.

Accessibility settings are stored in `user://audio_settings.cfg`:

- **Volume:** separate Master, Music, Ambient, SFX and Voice volumes (0..1). Setting a volume to 0 mutes that bus. The pause menu has a slider for each, plus the reduce-startling-audio toggle.
- **`reduce_startling_audio`:** cues flagged `startle` play 10 dB quieter and fade in over 0.6 s.
- **`music_intensity_cap`:** caps how intense the music can get.
- **Subtitles:** these are always emitted, so no information depends on audio alone.

**Clinical/narrative rule:** AudioDirector never listens to Objectivity or bleed-stage changes. Anomaly audio can only be started by an explicit narrative event in `cues.json`. A test enforces this.

**Merge note:** the unmerged `claude/sprint-01-foundation` branch (PR #1) has its own `Settings` autoload with volume sliders and a `default_bus_layout.tres` (Ambient/Voice/Music). When that branch is merged, keep a single source of truth for volumes: either have `Settings` call `AudioDirector.set_setting`, or move the audio keys into `Settings`. AudioDirector already reuses buses with the same names.

| `music_ending_credits.ogg` | `mus_ending_credits` | music context `ending_credits` (event `music_credits`) | plays once | stopped |

How playback works:

- **Contexts take over the music and hand it back.** Contexts stack: the newest plays, and ending it returns to the one below or, when none is left, to the location's music state and ambience. A context whose track plays once ends by itself. While a context is active, room changes keep its music, and a context that stops ambience keeps the world silent behind it.
- **Exploration follows the room.** Only the records archive carries the exploration state, by day. `records_archive` exists in `audio/cues.json` but no zone in `data/zones.json` has an archive `audio_zones` rectangle yet; the world owner adds one with the archive. The corridor, nursing station, Ward Zero, the historical wing and every location at night have no music state, so entering them fades the exploration theme out and leaves the ambience and its controlled silence. Music started explicitly (`play_music`, an event's `music_state`) is not stopped by room changes.
- **Repeats.** None of the tracks is a seamless loop: each has a composed fade-in and ending, and `music_narrative.ogg` ends at full level. So the imports keep `loop=false`, and AudioDirector repeats them itself: `loop_crossfade` crossfades the tail into a fresh start, `tail_fade` with `repeat_after` fades the ending out and rests in silence first. Pausing the game pauses the rest as well.
- **Dialogue.** Every track is on the Music bus, so dialogue ducks it by 9 dB. A context's ambience duck adds to the dialogue duck instead of replacing it.
- **Triggers.** Story data fires the events above through `EventBus.narrative_event_fired`, or code calls `AudioDirector.start_music_context(id)`. No scene fires the main-menu, cinematic, emotional or credits events yet, because the game has no title screen, cinematics or credits scene, and no story beat is marked emotional. Those scenes should fire the events when they are built.
- `music_main_theme.m4a` (an Opus copy of the main theme) is ignored: Godot cannot import `.m4a`.

## Regenerating assets

```sh
python3 -m venv .venv-audio
.venv-audio/bin/pip install -r tools/audio/requirements.txt
mkdir -p tools/audio/models && cd tools/audio/models
curl -LO https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.onnx
curl -LO https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
cd ../../..
.venv-audio/bin/python tools/audio/synth_sfx.py          # all procedural assets (deterministic seeds)
.venv-audio/bin/python tools/audio/generate_voice.py     # only new/changed lines
.venv-audio/bin/python tools/audio/build_manifest.py     # refresh manifest + docs/AUDIO_MANIFEST.md
```

Then open Godot once (or run `godot --headless --path . --editor --import`) so it imports new files, and run `python3 tests/qa/run.py`.

To add dialogue, add lines to `data/narrative/*.json` with a new stable `id` and a `speaker` that exists in `voice_profiles.json`, then run `generate_voice.py`. If you change a line's text, its clip becomes stale and `build_manifest.py --check` reports it.

Model files used (SHA-256): `kokoro-v1.0.onnx` `7d5df8ec…6c5`, `voices-v1.0.bin` `bca610b8…bf7d`.

## Tests

- `tests/audio/TestAudio.tscn`: 211 assertions in headless Godot (many are per-asset checks). They cover buses, volumes, mute and clamping; that every manifest asset loads and matches its duration; voice clips for every line; day/night/location ambience and reverb; 2D and 3D events; that unmapped events stay silent and one-shots clean up; startle reduction; the intensity cap; subtitle timing against clip length; skip/stop; positional dialogue; that bleed stage alone triggers no audio; music-state variant crossfades; dialogue ducking and recovery; multi-take randomizers; detail ambience layers; Ward Zero acoustics; and anomalies that only play from explicit events and are softened by the accessibility option.
- `scenes/audio/Ch1AudioSequence.tscn -- --exit-when-done`: runs the full Chapter 1 sequence (about 61 s) and checks the order of beats.
- `tests/qa/test_audio_manifest.py`: checks, using only the standard library, that the manifest matches the files and that cues, events, lines and profiles are consistent.
- `tests/music_ai/test_generate_music.py`: tests the ACE-Step client against a **mock** server: submit, poll, download, decode check, loudness, loop seam, import. It does not test ACE-Step itself.

Headless Godot uses the Dummy audio driver, so these tests confirm playback state and timing but not how anything sounds. Listening review is manual: the 11 soundtrack tracks are now `approved_listening_review` by the owner decision above. Other assets retain their existing review status; headless tests do not supply listening approval.

## Known limitations

- The procedural assets are functional placeholders. Synthesized door, pager and ambience are plausible but not Foley-grade. The transition is a synthesized sketch, **not** the AI score.
- TTS pronunciation and delivery have not been reviewed by ear. No speech recognition was available offline to check them automatically.
- Distant staff walla is Kokoro speech low-passed at 1.1 kHz, so a few words may still be audible. It is harmless filler text from `data/narrative/walla.json`, which must never carry clues.
- Night currently reuses the day beds with filtering. There is no dedicated night or reception bed yet.
